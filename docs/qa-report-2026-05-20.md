## Notes on Minor Issues Found

1. **Redundant `sr` class + `scrollReveal` directive**: In `home.component.html` at lines 183, 188, and 213, elements have the explicit `sr` class AND the `scrollReveal` directive (which automatically adds `sr` via `host: { class: 'sr' }`). This results in a duplicate class attribute but causes no functional or build error.

2. **Ghost button not in design system**: The spec mentions "ghost CTA button" for the portfolio cards on the home page. The current implementation uses `button button--sm`, which is correct — there is no `button--ghost` class defined in `styles.scss`. The `button` base class renders as an outlined ghost-style button by default (transparent background, border, hover accent), so the intent is met.

3. **Hardcoded `h1` text on portfolio page**: The portfolio page hero has `<h1 class="gradient-text sr" scrollReveal [delay]="80">Portfolio</h1>` with the heading text hardcoded as "Portfolio" rather than from a content key. This is consistent across all three languages and causes no errors but is slightly inconsistent with the i18n pattern used elsewhere.

4. **No `portfolio` entry in `GeoBreadcrumbs` interface or data**: The `GeoBreadcrumbs` interface (site-content.ts lines 267–277) and all breadcrumb data do not include a `portfolio` breadcrumb. This is not in the QA checklist and does not cause a build error, but should be noted for completeness if breadcrumb schema is ever added to the portfolio page.
